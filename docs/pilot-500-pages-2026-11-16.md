# 500-page corpus handoff: 2026-11-16

This run targets the lower planned corpus size, using the existing crawler and
audited JSONL handoff. Size/integrity checks and a sampled content review are
separate from acceptance by the real indexer and general extraction accuracy.

## Profile and replay

[`config/pilot-500-pages.json`](../config/pilot-500-pages.json) has 12 ordered
English seeds across six allowed hosts. It keeps Python, RFC Editor, SQLite,
PostgreSQL and GNU, and adds `www.kernel.org`'s Linux documentation. A one-target
probe of its documentation index delivered an English page under the normal
scope/robots policy before the larger run.

A preliminary five-host attempt was stopped after both PostgreSQL seeds returned
`request_denied`, leaving only four hosts delivering pages. Its partial outputs
are not a completed snapshot and are not merged into this corpus. The revised
profile retains PostgreSQL and adds the independently verified documentation host.
`request_denied` combines caller scope/robots checks; the journal does not identify
the particular check/hop or prove a site's permanent policy.

Limits are 500 delivered pages, 1500 targets, depth 2, 3000 pending URLs, 500 pending
per canonical host, 5000 total admitted URLs and a 900000 ms scheduling budget.
The larger queue allows up to six 500-entry host backlogs; it is still bounded,
and capacity rejections remain possible. This does not reserve equal page counts.
One-second host delay, redirect checks, robots rules, English admission, exact
URL/text deduplication, timeouts and the 2 MiB HTTP body cap remain enabled.

Create `data/` and choose new paths; the executable refuses existing outputs:

```powershell
./build/release/crawler/hfs-crawler.exe crawl --config config/pilot-500-pages.json --output data/pilot-500-corpus.jsonl --log data/pilot-500-log.jsonl --manifest data/pilot-500-run.json
python tools/verify_run.py data/pilot-500-run.json --check-pages
python tools/package_run.py data/pilot-500-run.json --output data/indexer-handoff-500.zip --source-commit 8aaf7903f068cd5ee3e884c9352a452df67538d3
```

That source hash identifies the unchanged crawler code used here, not arbitrary
future reruns. Supply the actual producing revision for another run. The packager
records this caller declaration; the manifest itself has no Git/binary hash.
The new profile and report are committed in this increment. The Release executable
uses MinGW GCC 15.2.0, `semantic-text-v4`, `depth-host-round-robin-v1`,
`lexbor-url-v1` and `cld2-compact-v1`.

## Observed results

### Earlier completed shortfall

The first completed six-host run (`data/pilot-500-20261116T174606Z-run.json`)
exited 0 at `target_limit`: 438 delivered pages, 1500 targets, 919 fetch failures
and 1121 pending URLs after 688382 ms. Of those failures, 900 were `http:transport`
with `Could not resolve hostname`, across all five delivering hosts. The journal
records the symptom; its root cause is not established. Artifact/page audit and
the independent per-row journal/timestamp checks passed for the 438 saved pages.

After a bounded control HTTPS request succeeded, the same profile was rerun into
fresh files. The shortfall snapshot is kept separately, without merging or
inventing a single-run manifest. These results also show that an outage can
consume the target budget: the current crawler continues within its limits
rather than applying a run-wide transport-error backoff.

## Content review and remaining work

The read-only artifact/page verifier passed for all 500 records. An additional
local audit recomputed URL/text hashes, checked uniqueness and allowed request
chains, matched every row with its delivered journal event (initial/final URL,
depth, response and language), and checked UTC timestamps against the run.
The C++ crawler is unchanged in this increment; the packaging test suite was
rerun after adding this report to its explicit public-document list.

Thirty-five distinct records were sampled at their start (250 characters),
middle (200) and end (200): first/last per host, two shortest and the longest per
extraction branch, first depth-2 delivery per host, and seven follow-up records
from the in-progress review, with overlaps removed. Saved sample selections and
analysis are local at `build/pilot-500-review.json`.

- SQLite body fallbacks still retain repeated menu/search text, including the
  developer, self-contained and FTS5 pages. The PRAGMA heading selection and
  feature overview retain useful explanatory content. Source labels expose
  selection, not a binary quality verdict.
- PostgreSQL samples include useful project/policy prose alongside short
  download directories with a release banner, and a 222-character conference
  photo-page instruction. Shortness and English admission do not prove usefulness.
- Kernel documentation includes technical prose such as atomic types, but
  language-selection labels can remain inside the semantic region. Its
  `genindex.html` is a 556389-character alphabetical symbol index, not a single
  explanatory article; it is the largest record in this snapshot.
- RFC topic pages retain sorting/display/subscription controls and long abstract
  lists. Python samples include short job/category listings and a
  104391-character Windows release/download list.

The minimum planned volume and five delivering hosts are reached. This is an
audited development corpus, not a fully curated relevance set: near duplicates,
directories, boilerplate and statistical language errors remain possible. Exact
hash deduplication does not establish semantic uniqueness. Further corpus
curation and the actual indexer's ingestion/update/search acceptance remain
separate work. Long documents need the indexer's own tokenization/chunking;
the crawler applies no embedding-model token limit.
