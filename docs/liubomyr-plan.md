# План работы Liubomyr

Источник требований: `human-first-search.pdf`, 2 страницы. Это план реализации, а не согласованная командой архитектура. При первоначальном анализе репозиторий был пустым; текущее состояние описано ниже.

## Выполнено: каркас

- Добавлены CMake/Ninja-пресеты Debug/Release, библиотека crawler_core и CLI hfs-crawler.
- CLI поддерживает --help/-h и --version; неверные аргументы завершаются кодом 2 и диагностикой в stderr.
- Обе конфигурации собраны и запущены на MinGW-w64 GCC 15.2.0; CTest проверил шесть сценариев CLI в каждой конфигурации.
- Каркас переведён на C++20: CliResult использует std::variant, вывод — стандартные потоки; дополнительная библиотека поддержки терминала не требуется.
- Комментарии к коду написаны на английском; инструкции запуска находятся в README.md.
- Загрузка страниц, конфигурация обхода, HTML и JSONL ещё не реализованы. Следующий шаг — локальная HTML-фикстура и экспорт.

## Выполнено: выбор HTML-парсера

- Выбран Lexbor 3.0.0 (Apache-2.0), подключён через FetchContent с фиксацией полного commit SHA.
- На MinGW GCC 15.2.0 собраны Debug/Release; тест C++ API проверил разбор HTML с пропущенными закрывающими тегами и декодирование сущности в заголовке. CLI-тесты также прошли.
- Проверка использовала локальный checkout нужной версии; автоматическое сетевое скачивание FetchContent пока не проверялось.
- Обоснование и ограничения описаны в html-parser.md.

## Выполнено: обёртка HTML-документа

- HtmlDocument скрывает типы Lexbor, владеет DOM через RAII, запрещает копирование и поддерживает перемещение.
- Метод title() возвращает независимую строку с декодированными сущностями и нормализованными пробелами; отсутствие заголовка даёт пустую строку.
- Debug/Release собраны; все три CTest-теста проходят, включая проверки времени жизни входа, результата и перемещения документа.
- Чтение файлов, основной текст, ссылки и JSONL ещё не реализованы. Следующий небольшой шаг — извлечение текста из DOM на локальных примерах.

## Выполнено: базовый текст body

- Это кандидаты на ссылки: нормализация, base URL, разрешённые схемы/домены и robots.txt будут обрабатываться до постановки в очередь отдельными компонентами.

- F03: извлечение основного текста, заголовка и ссылок; нормализация URL; удаление точных дубликатов.
- F04: воспроизводимый JSONL-корпус со стабильными ID, URL, метаданными и хешами текста.

## Принятый стек и автономная работа

Используем C++20 + CMake + Ninja + GCC (g++ для C++). В CMake: CXX_STANDARD 20, CXX_STANDARD_REQUIRED ON, CXX_EXTENSIONS OFF; Debug/Release через CMakePresets.json, сборка вне дерева исходников.

Локально обнаружены g++ 15.2.0 (MSYS2 MinGW-w64), CMake 4.2.1 и Ninja 1.13.2. Целевой стандарт — C++20; применяемые возможности языка и библиотеки проверяем сборкой и запуском Debug/Release.

До сообщения пользователя о начале совместной интеграции разрабатываем автономно. Не ждём согласований других участников. JSONL документируем как предварительный контракт и проверяем локально через фикстуры и независимый Python-reader. Совместные проверки F16 остаются будущим этапом: их нельзя считать выполненными по локальным заглушкам. Указанные ниже передачи корпуса и совместные этапы выполняются после возобновления командной работы; календарные сроки ориентировочные.

## Предлагаемая конструкция

Один локальный CLI-процесс, один поток на старте, без распределённой очереди и обязательной базы данных. Используем принятый выше стек, libcurl для HTTP и JSON-библиотеку для экспорта. HTML и robots.txt следует обрабатывать готовыми подходящими библиотеками; конкретные зависимости выбрать после проверки сборки и лицензий. Не разбирать HTML регулярными выражениями.

Модули:

- `config`: seeds, разрешённые хосты, ограничения, User-Agent, задержки и пути вывода.
- `url`: разрешение относительных ссылок, нормализация и проверка границ обхода.
- `http`: загрузка с ограничениями времени, размера, типа ответа и числа перенаправлений.
- `robots`: получение, кеширование и применение правил для выбранного User-Agent.
- `frontier`: очередь, учёт посещённых URL и расписание запросов по хостам.
- `extractor`: DOM-разбор, title, основной текст, ссылки и определение языка.
- `corpus`: хеши, точная дедупликация и JSONL-экспорт.
- `crawl_log`: причины пропуска, HTTP-ошибки и сводная статистика.

Предварительная структура: `crawler/include/`, `crawler/src/`, `crawler/tests/`, `config/`, `fixtures/`, `docs/`. Это предложение; Python backend и frontend команда добавит отдельно.

## Предварительный контракт для будущей интеграции с Maksym

Одна строка JSONL — одна страница; UTF-8; без разбиения на passages. Минимальная предлагаемая запись:

```json
{"schema_version":1,"page_id":"sha256:<normalized-url-hash>","url":"https://example.org/article","title":"Example article","text":"Main page text...","language":"en","text_hash":"sha256:<normalized-text-hash>","fetched_at":"2026-11-01T12:00:00Z","http_status":200,"content_type":"text/html"}
```

Правила, которые нужно явно зафиксировать:

- `page_id` зависит от нормализованного конечного URL, а `text_hash` — от нормализованного извлечённого текста. Изменение содержимого не меняет ID страницы при неизменном URL.
- Отдельно описать нормализацию текста: Unicode, пробелы и переносы. Версионировать правила извлечения и нормализации.
- Совпадения `text_hash` означают точные дубликаты по выбранным правилам. Выбирать представителя детерминированно при экспорте; URL-дубликаты отражать в журнале или отдельном файле соответствий.
- URL: удалить fragment, привести scheme/host к нижнему регистру, разрешать относительные пути. Сохранять регистр path и значимые query-параметры; не удалять все параметры и не склеивать HTTP/HTTPS без основания.
- Проверять разрешённый хост и robots.txt до загрузки каждой страницы, включая каждый переход перенаправления. Поддомены разрешать явно.
- Не доверять одному `html lang` для проверки английского текста. Выбрать лёгкий детектор и определить поведение для коротких и неопределённых текстов.
- Фиксировать requested URL, конечный URL и перенаправления в метаданных/журнале.

Воспроизводимость означает повторяемую обработку сохранённого снимка корпуса, а не гарантию одинакового содержимого живого интернета. Сохранять seeds, конфигурацию, версии инструментов, манифест и хеш экспортированного корпуса; для демонстрации использовать локальные фикстуры. Временные метки не включать в вычисление стабильных ID.

5. Добавить очередь и лимиты; затем выполнить небольшой живой обход.
6. Улучшить качество извлечения и языка на реальных образцах; после этого масштабировать корпус.

## Существенные проверки

- Относительные ссылки, fragment, query и повторные URL обрабатываются предсказуемо.
- robots.txt запрещает реальные запросы, в том числе после redirect; off-domain redirect не выходит за allowlist.
- Соблюдаются задержки между запросами к хосту; ошибки не запускают бесконечные повторы.
- Таймауты, циклы redirect, большой ответ, не-HTML и неподдерживаемая кодировка не останавливают весь запуск.
- Отдельно ограничены количество принятых страниц, попыток запросов, глубина, очередь, размер ответа и общая длительность.
- Повторная обработка одинаковых фикстур даёт те же ID, хеши и порядок записей; JSONL читается Python.
- Навигация и скрипты не попадают в основной текст; неанглийские и пустые страницы получают понятную причину пропуска.
- Интеграционные проверки F16 распределить между владельцами компонентов. Liubomyr координирует, но не подменяет реализацию Maksym и Viktor.

## Ближайший результат

Первый инкремент: воспроизводимая сборка и конвертация локальной HTML-страницы в JSONL. Следующий: небольшой корректный обход с robots.txt. Библиотеки и домены пока выбираем автономно; окончательный JSONL-контракт согласуем при совместной интеграции.
